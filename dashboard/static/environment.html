1. システムの目的と全体概要

Cloud Isolated Honeypot

本システムは、インターネット上に存在する無差別なサイバー攻撃や自動スキャン（ボットネット活動）を安全におびき寄せて観測し、収集した攻撃データを機械学習（AI）で自動分類・可視化して一般公開するための「クラウド隔離型ハニーポット・脅威インテリジェンス基盤」です。

通常のWebサーバーは攻撃をブロック（防御）することを目的としますが、本システムはあえて無防備なWebサーバーや古いルーターの挙動を模倣する「おとり（ハニーポット）」としてインターネットに公開します。世界中から送り込まれる不正リクエストの送信元IP、HTTPヘッダ、ペイロード（攻撃コマンド）をリアルタイムに記録し、別の専用プロジェクトへ自動隔離したうえで、安全な統計データへと無害化・加工し、誰もがブラウザから閲覧できるWebダッシュボードとして公開する一連のパイプラインを備えています。

2. システム全体の4層アーキテクチャ

Zero Trust / Isolation
図1：クラウド隔離型ハニーポット・脅威インテリジェンス 4層アーキテクチャとデータフロー

① おとり観測層（本番ハニーポット環境：honeypot-515503）

Google Cloud（GCP）の Compute Engine（e2-micro / 米国リージョン us-central1）上に、コンテナ特化型OSである Container-Optimized OS（COS）を採用して構築しています。Python製の軽量HTTPハニーポット（honeypot.py）が80番ポートで待ち受け、アクセスに対して偽装レスポンス（Server: nginx およびダミーHTML）を返却しつつ、リクエストの全容を構造化JSON形式で標準出力へ書き出します。万が一の放置による課金やリスクを防ぐため、インスタンス作成から7日間で自動削除される使い捨て設計（--max-run-duration=7d）を組み込んでいます。

② 多層防御・踏み台化防止ネットワーク層（カスタムVPC：hp-vpc）

  • 外向き通信の完全遮断（Egress Deny）: ファイアウォールルールにより、ハニーポットから外部インターネットへの発信通信をすべて拒否しています。
  • 限定公開 Google アクセス（Private Google Access）: 外部ネットを遮断したままコンテナイメージの取得（Artifact Registry）とログ送信（Cloud Logging）のみを行えるよう、Cloud DNS のプライベートゾーンとファイアウォールで Google API 専用IP帯域（199.36.153.8/30）への通信だけを例外的に許可しています。
  • コンテナのハードニング: Dockerコンテナ起動時に「読み取り専用ファイルシステム（--read-only）」「全Linuxケーパビリティ剥奪（--cap-drop=ALL）」「非特権ユーザー実行（nobody）」「GCPメタデータサーバー（169.254.169.254）への通信遮断」を適用しています。
  • 管理経路の暗号化（IAP トンネル）: SSH（22番ポート）はインターネットに公開せず、Identity-Aware Proxy（IAP / 35.235.240.0/20）を通じた認証済み暗号化トンネル経由でのみ接続を許可しています。

③ ログ自動隔離・保全層（ログ専用プロジェクト：honeypot-logs-515503）

攻撃者がハニーポット側の権限を侵害して証拠隠滅を図るリスクを排除するため、ログの保管場所を本番環境とは別のGCPプロジェクトへ完全に分離しています。本番プロジェクトの Cloud Logging に出力されたコンテナログは、GCP内部バックボーンを通る「ログシンク（ログルーター）」によって検知された瞬間に隔離プロジェクトのログバケットへリアルタイム転送されます。本番環境には隔離先ログの削除・編集権限を持たせない一方向（Write-Only）の設計です。

④ AI分析・一般公開層（Cloud Run ＆ FastAPI ダッシュボード）

隔離プロジェクトに蓄積されたログを外部へ公開するためのWebアプリケーション層です。Cloud Run 上で FastAPI（Python）と HTML / CSS / JavaScript によるダッシュボードを稼働させ、閲覧専用（roles/logging.viewer）の最小権限を持つサービスアカウントで隔離ログを読み取ります。TF-IDF + Multinomial Naive Bayes と Isolation Forest による攻撃分類・異常検知、GeoIPマッピング、無害化（サニタイズ）、GCP推定コスト算出をリアルタイムに行います。

Live Observation

本システムをインターネット上に公開した初期稼働テストでは、公開からわずか1時間以内に世界各国（南アフリカ・インド・ブラジル等）のISP配下にある複数のボットネット端末から、ルーターのコマンドインジェクション脆弱性（/boaform/admin/formSysCmd）を狙った一斉攻撃を観測しました。ペイロード解析により、ホスティング事業者配下にあるC2サーバー（45.90.163.37:4545）へリバースシェルを接続させようとする分散型攻撃インフラの構造を特定・記録しつつ、多層防御によって外部への発信通信を完全に遮断できることが実証されています。

6. セキュリティ補強・安全設計と運用機能

Hardened & Operational

XSS・インジェクション対策

攻撃者の送信元IP、ISP名、リクエストパス、攻撃ペイロードなどの外部由来データを innerHTML やHTML文字列結合で差し込まず、textContent および document.createElement() ベースで描画することでスクリプト解釈やDOMインジェクションを防止しています。バッジクラス名のホワイトリスト制限や、地図ポップアップ・座標・件数の妥当性チェックも組み込んでいます。

バックエンド入力サニタイズ・リソース保護

制御文字の除去や表示長の上限設定（…(truncated) による切り詰め）により、長大・不正なペイロードによる表示崩れや負荷を抑えています。GeoIPキャッシュやレスポンスキャッシュには上限数とTTLを設けてメモリ肥大化や過剰な外部照会を防ぎつつ、静的ファイル配信時のパス検証、セキュリティヘッダー（X-Content-Type-Options、X-Frame-Options、Referrer-Policy）の付与、ストリームエラー時の内部情報秘匿、外部送信（Egress）制限による踏み台化防止を組み合わせた構成としています。

最小権限（IAM）・運用機能

ダッシュボード閲覧用サービスアカウントを分離し、必要な閲覧権限（roles/logging.viewer）に絞った最小権限運用を行っています。画面上では日本語／英語のUI切替、リアルタイムSSEストリームの一時停止・再開・即時取得、送信元IP・国・ISP・ペイロードを横断する検索・フィルタリングなどの分析・運用機能に対応しています。

1. Purpose & System Overview

Cloud Isolated Honeypot

This system is a cloud-isolated honeypot and threat intelligence platform designed to safely attract and observe indiscriminate cyberattacks and automated botnet scans on the internet, classify and score threats using machine learning, and visualize sanitized telemetry on a web dashboard.

While typical web servers aim to block attacks, this system intentionally exposes a decoy web/router endpoint (honeypot.py) to capture real-world source IPs, HTTP headers, and exploit payloads in real time. Captured events are automatically routed to an isolated logging project, sanitized for safe public display, and streamed to a responsive FastAPI + Leaflet.js + Chart.js dashboard.

2. Four-Layer Architecture

Zero Trust / Isolation
Figure 1: Four-Layer Cloud-Isolated Honeypot & Threat Intelligence Architecture

1. Decoy Observation Layer (Production Honeypot: honeypot-515503)

Built on Google Cloud Compute Engine (e2-micro in us-central1) running Container-Optimized OS (COS). A lightweight Python HTTP honeypot listens on port 80, returns a plausible decoy response (Server: nginx and dummy HTML), and emits structured JSON logs to stdout with an automatic 7-day maximum run duration (--max-run-duration=7d).

2. Defense-in-Depth Network Layer (Custom VPC: hp-vpc)

  • Outbound Egress Deny: Firewall rules block general outbound internet traffic from the honeypot so it cannot be abused as a pivot or DDoS source.
  • Private Google Access: Private DNS and firewall allow-rules restrict traffic solely to Google APIs VIP (199.36.153.8/30) for pulling container images from Artifact Registry and writing Cloud Logging entries.
  • Container Hardening: Runs with a read-only root filesystem (--read-only), all Linux capabilities dropped (--cap-drop=ALL), non-root user (nobody), and blocked access to the GCE metadata endpoint (169.254.169.254).
  • Encrypted Management via IAP: Direct public SSH (port 22) is closed; administrative access is permitted only through Identity-Aware Proxy (IAP / 35.235.240.0/20).

3. Log Isolation & Preservation Layer (honeypot-logs-515503)

Logs are routed via a Cloud Logging sink over Google's internal backbone to a separate log-isolation GCP project. The honeypot runtime has no permission to alter or delete isolated logs, preserving forensic integrity even if the decoy container is compromised.

4. AI Analytics & Visualization Layer (Cloud Run & FastAPI)

A FastAPI backend running on Cloud Run reads isolated logs using a least-privilege viewer service account (roles/logging.viewer), performs TF-IDF + Multinomial Naive Bayes classification and Isolation Forest anomaly scoring, resolves GeoIP/ISP metadata, sanitizes sensitive fields, and streams live updates via Server-Sent Events (SSE).

5. Initial Field Observations

Live Observation

Within the first hour of initial internet exposure, automated scanners and botnet nodes across multiple regions (including South Africa, India, and Brazil) probed router command-injection endpoints such as /boaform/admin/formSysCmd with reverse-shell payloads (e.g., nc ... 4545|sh targeting 45.90.163.37:4545), while egress controls prevented outbound connections from the honeypot.

6. Security Hardening, Safety & Operational Features

Hardened & Operational

XSS & DOM Safety

Untrusted external fields such as source IPs, ISPs, paths, and payloads are rendered using textContent and document.createElement() rather than innerHTML or raw HTML string concatenation. Badge class names are allowlisted, and map popups, coordinates, and counts are validated before rendering.

Input Sanitization & Resource Protection

Control characters are stripped and long fields are bounded with truncation (…(truncated)) to prevent layout breakage or heavy load from oversized or malformed payloads. GeoIP and response caches use size limits and TTLs, paired with static path validation, security headers (X-Content-Type-Options, X-Frame-Options, Referrer-Policy), redaction of internal error details in streams, and outbound egress restrictions.

Least-Privilege IAM & Operations

A dedicated viewer service account restricts log access to roles/logging.viewer. The UI supports Japanese/English switching, real-time SSE stream pause/resume/immediate refresh, and search/filtering across IP, country, ISP, and payload fields.
