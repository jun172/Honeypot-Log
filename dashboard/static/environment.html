1. システムの目的と全体概要

Cloud Isolated Honeypot

本システムは、インターネット上の自動スキャンや不正アクセス試行を安全に観測・記録し、送信元情報やリクエスト内容を構造化ログとして収集・可視化するためのクラウド隔離型ハニーポット基盤です。

プロジェクト honeypot-515503 上の仮想マシン hp-vm-us-01（外部IP: 34.170.152.225）にて、リバースプロキシの hp-nginx（8080番ポート公開）とハニーポット本体の honeypot を内部ネットワーク hp-internal 上で連携稼働させています。アクセスは非特権ユーザー hpuser で実行される honeypot へ渡され、Egress 制限や IAP 経由 SSH、Cloud Logging 連携を組み合わせることで、外部への踏み台化を抑止しつつ観測ログを安全に記録します。

2. システム全体の4層アーキテクチャ

hp-vpc / hpuser / IAP
図1：honeypot-515503 / hp-vm-us-01 中心の観測・隔離・Cloud Logging 構成図

① おとり観測層（プロジェクト：honeypot-515503 / VM：hp-vm-us-01）

Compute Engine インスタンス hp-vm-us-01（外部IP: 34.170.152.225）上で、リバースプロキシの hp-nginx とハニーポット本体の honeypot コンテナを稼働させています。外部からの 8080 番ポートへのアクセスを hp-nginx が受け付け、Docker 内部ネットワーク hp-internal 経由で honeypot へ転送します。

② ネットワーク・非特権実行による隔離層（VPC：hp-vpc / ユーザー：hpuser）

  • コンテナの非特権ユーザー実行（hpuser）: ハニーポットプロセスは特権 root ではなく hpuser として動作し、コンテナ内部で万が一処理が逸脱した場合でもホストや権限昇格のリスクを抑えます。
  • ネットワーク分離と公開ポート制御: hp-vpc（サブネット hp-subnet-us）および Docker ネットワーク hp-internal によって内部通信を分離しつつ、公開用ルール hp-allow-honeypot-8080 で 8080 番ポートを公開しています。
  • Egress 制限: hp-allow-pga-egress（199.36.153.8/30 宛て TCP 443）と hp-deny-all-egress（外向き通信拒否）により、VM から外部インターネットへの無制限な送信通信を制限しています。
  • IAP 経由 SSH 制限: hp-allow-iap-ssh により SSH（TCP 22）は Identity-Aware Proxy（35.235.240.0/20）経由のみへ限定しています。

③ ログ収集・記録層（Cloud Logging ＆ コンテナログ）

hp-nginx および honeypot が記録するリクエスト・アクセス・検知ログはコンテナログおよび Cloud Logging へ出力されます。公開後の外部アクセスやスキャン試行を後から追跡・分析できるよう、観測証跡を保持します。

④ アクセス制御・可視化層（IAM 最小権限 ＆ Web UI）

運用アカウント（mujwtaxz@gmail.com）のプロジェクトロールは roles/viewer（および IAP 接続用の roles/iap.tunnelResourceAccessor）へ絞り込み、誤変更や不正削除を防いでいます。Web 画面ではダッシュボードと本構成ページ（日本語／英語切替）を提供します。

Least Privilege & Isolation

非特権実行（hpuser）とネットワーク分離

honeypot コンテナを非特権ユーザー hpuser で動作させ、hp-nginx とは hp-internal ネットワーク経由で通信させることで、外部公開口とアプリケーション処理の境界を整理しています。

Egress 制限と IAP 経由 SSH

hp-vpc 上の Egress 制限ルール（hp-allow-pga-egress / hp-deny-all-egress）で外部への不要な送信を抑止しつつ、管理用 SSH は IAP（35.235.240.0/20）経由に限定しています。

IAM 最小権限と Cloud Logging 確認

運用アカウントの権限を roles/viewer（＋ roles/iap.tunnelResourceAccessor）に抑えることで、意図しないリソース変更や削除を防ぎつつ、Cloud Logging やコンテナログから公開後のアクセス状況を把握できます。

1. Purpose & System Overview

Cloud Isolated Honeypot

This system is a cloud-isolated honeypot environment designed to observe and record external scans and HTTP access attempts while limiting outbound risk and preserving audit visibility via Cloud Logging.

Running on Compute Engine instance hp-vm-us-01 (external IP: 34.170.152.225) in project honeypot-515503, the deployment pairs reverse proxy hp-nginx (exposed on port 8080) with honeypot container honeypot running as non-root user hpuser over internal network hp-internal. Outbound egress restrictions, IAP-only SSH, Cloud Logging, and least-privilege roles/viewer IAM access support safe observation.

2. Four-Layer Architecture

hp-vpc / hpuser / IAP
Figure 1: Live Architecture Centered on honeypot-515503, hp-vm-us-01, hpuser, and Cloud Logging

1. Decoy Observation Layer (Project: honeypot-515503 / VM: hp-vm-us-01)

Hosted on Compute Engine instance hp-vm-us-01 (external IP: 34.170.152.225), running reverse proxy hp-nginx and honeypot container honeypot connected via Docker network hp-internal. Requests arriving on port 8080 are proxied to honeypot for decoy responses and logging.

2. Network & Non-Root Isolation Layer (VPC: hp-vpc / User: hpuser)

  • Non-Root Container User (hpuser): The honeypot runs as non-privileged user hpuser rather than root to reduce privilege-escalation impact.
  • VPC & Port Exposure: Uses hp-vpc (hp-subnet-us) and hp-internal for internal container separation, with hp-allow-honeypot-8080 exposing port 8080.
  • Egress Controls: Rules such as hp-allow-pga-egress (199.36.153.8/30 TCP 443) and hp-deny-all-egress constrain unrestricted outbound traffic from the VM.
  • IAP-Only SSH: SSH (TCP 22) is restricted via hp-allow-iap-ssh to Identity-Aware Proxy (35.235.240.0/20).

3. Logging & Audit Layer (Cloud Logging & Container Logs)

Access and application output from hp-nginx and honeypot are recorded in container logs and Cloud Logging to preserve visibility into external requests and scan activity.

4. Least-Privilege Access & Visualization Layer

Operator IAM access is narrowed to roles/viewer (along with roles/iap.tunnelResourceAccessor for IAP SSH), preventing unintended edits or deletions while supporting log review and bilingual UI navigation.
